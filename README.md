# Telegram Data Analyst Userbot

Асинхронный Telegram userbot для сбора истории чата и подготовки краткого отчёта. Основной обработчик использует Qwen3.6 35B через Yandex AI Studio для текста. Анализ изображений пока не подключён.

## Как работает текущая версия

1. `main.py` запускает Pyrogram-клиент.
2. `src/bot/handlers.py` ждёт команду `.summary` от владельца аккаунта.
3. Обработчик собирает до 50 последних сообщений, включая текст и подписи к медиа.
4. Для изображений сейчас определяется только факт наличия: файлы не скачиваются и модели не передаются.
5. `src/models/yandex_client.py` отправляет текст в Yandex AI Studio и возвращает саммари обработчику.
6. Обработчик отправляет результат в «Избранное».

## Активные файлы

- `main.py` — точка входа приложения.
- `src/auth.py` — вход в Telegram и создание локальной сессии.
- `src/bot/handlers.py` — команда, сбор истории и отправка результата.
- `src/models/yandex_client.py` — текущий текстовый клиент Yandex AI Studio.
- `.env` — локальные секреты (`API_ID`, `API_HASH`, `YANDEX_CLOUD_API_KEY`, `YANDEX_CLOUD_FOLDER`); файл игнорируется Git.
- `src/analyst_userbot.session*` — локальная Telegram-сессия; секрет, не добавлять в Git и никому не отправлять.

## Архив экспериментов

Старые ноутбуки, черновики промптов, пробный HF-клиент и отдельная проверка Gemini перемещены в `archive/experiments/`. Они не вызываются основным приложением и оставлены для справки.

## Запуск

1. Установите зависимости в виртуальное окружение: `pyrogram`, `httpx`, `python-dotenv`.
2. Проверьте локальный `.env`: для текущего текстового клиента нужны `YANDEX_CLOUD_API_KEY` и `YANDEX_CLOUD_FOLDER`. Не публикуйте файл и не вставляйте секреты в сообщения.
3. После отзыва старой Telegram-сессии, когда будете готовы к сквозной проверке, создайте новую:

```powershell
python .\src\auth.py
```

4. Запустите приложение из корня проекта:

```powershell
python .\main.py
```

5. В нужном чате отправьте `.summary`.
